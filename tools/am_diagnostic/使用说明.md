# 怒喵鼠标诊断工具 v1.1（Windows）

v1.1 修正 Windows HID 按钮能力表结构大小，避免读取能力表时越界；跳过系统保留集合；发送查询前先打开输入通道，避免漏收快速响应；对 .97 接收器的 Output/Input 通道先查询目标 0，再尝试已存在的 0x80 路由。仍不设置链路模式或配对。

此工具用于收集型号、HID 接口和 DPI 响应，供后续适配。不是鼠标设置软件，不会修改 DPI、回报率、按键、灯光、配对或固件。不联网、不自动上传日志。

## 最简单的运行方法

1. 把整个 ZIP 复制到怒喵鼠标所在的 Windows 电脑，解压到普通文件夹。
2. 关闭 AM Master、怒喵网页驱动及外设电量监视器，避免同时读取。实际移动鼠标将它唤醒。
3. 双击 `AM-Mouse-Diagnostic.exe`，按回车开始。无需安装 Python，通常不需要管理员权限。
4. 完成后，窗口会显示日志 ZIP 的完整位置，默认在工具旁边的 `logs` 文件夹。按回车退出。
5. 把新生成的 `AM诊断_日期_时间_随机字符.zip` 发回，并说明鼠标具体型号、运行时使用的是 USB 还是 2.4G、官方驱动能否正常读取 DPI。

建议分别运行两次：

- **2.4G**：保留对应接收器，拔下鼠标的数据线，将鼠标切到 2.4G 并唤醒，运行一次。
- **USB**：使用可传输数据的 USB 线连接鼠标；为便于区分，先拔下接收器，再运行一次。

两份日志都保留。不同运行会生成不同文件，不会覆盖。蓝牙不在本次 DPI 诊断范围内。如果电脑上有多只怒喵鼠标，建议每次只连接待测的那一只。

## 读取范围与限制

- AM Infinity .97：读取当前配置层、DPI 档位和电量。接收器只尝试已经存在的鼠标路由，不设置链路模式，不配对；因此接收器读取失败时，USB 日志尤其重要。
- AM Infinity .100：读取当前配置层、完整 DPI 块、版本/电量。接收器使用官方流程申请临时转发通道并查询状态，不发送配置写入命令。
- AM Infinity .100R2：只尝试官方已开放的 USB 配置接口。接收器只收集接口信息。
- 未确认的 PID、Boot 模式和系统鼠标/键盘集合不会发送 DPI 命令。只支持已确认的报告通道，其他通道会记录能力并跳过。
- “仅查询”仍需要通过 HID 发送查询报文；不是完全不发送 USB 数据。程序中没有 DPI 设置、灯光设置、配对或固件升级入口。
- 单个接口最多运行约 35 秒，枚举最多约 25 秒；异常会记录并继续。无响应、离线、权限不足或未识别的日志同样有分析价值。
- 解析成功只表示读取成功，不代表已经验证修改 DPI 或断电保存。

## 日志内容

`run.json` 记录工具和 Windows 版本；`inventory.jsonl` 记录怒喵候选接口；`interface_XX.jsonl` 记录报告 ID、查询报文、原始响应、解析数据及错误；`诊断摘要.txt` 便于直接阅读。

不采集鼠标移动、点击、键盘输入或屏幕内容。HID 路径转为散列标识，不输出 HID 序列号字段。原始协议响应会保留，其中可能含设备/固件自行返回的标识信息。

## 源码运行（可选）

安装 Python 3.10 或更新版本，在解压目录运行：

```powershell
py -3 .\source\am_diagnostic.py
```

仅枚举接口、不发送任何协议查询：

```powershell
.\AM-Mouse-Diagnostic.exe --inventory-only
```

自动运行并指定日志目录：

```powershell
.\AM-Mouse-Diagnostic.exe --no-pause --output .\logs
```

源码仅依赖 Python 标准库及随附的 `hid_win.py`，无需 pip 安装 HID 库。EXE 为 Windows x64 便携版，未进行代码签名。若系统阻止启动，可使用源码版本，无需关闭系统防护。
