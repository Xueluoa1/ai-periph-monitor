## 怎么使用

1. 将鼠标、键盘的 2.4G 接收器接入电脑，并唤醒设备。
2. 双击 `多品牌外设诊断工具.exe`（当前内含 v1.5；与带版本号文件相同），等待采集窗口自动结束。
3. 桌面会出现 `外设诊断日志_日期_时间_编号.zip`。把完整 ZIP 发给我即可。

无需安装 Python、额外驱动或管理员权限。通常数十秒，遇到接口超时最多约 3 分钟。
程序识别 Windows 实际桌面位置，兼容重定向/OneDrive 桌面。桌面无法写入时会改存 `%TEMP%\外设诊断日志`，窗口会显示位置。
若日志提示接口被占用，可以退出该设备的官方配置软件后再运行；工具不会替你关闭任何进程。

## 会采集什么

- 全部可枚举 HID 接口的 VID/PID、产品名、厂商字符串、固件版本标识、Usage、Report 长度和能力表。
- 匹配协议通道的查询请求、原始响应、失败/超时信息，以及电量、DPI、回报率、灯光的解码候选。
- 未匹配设备采集完整 Windows HID 解析能力表和声明的 Feature Report；符合条件的纯厂商输入接口额外短时采集主动上报，不猜测其他厂商命令。
- 普通键盘、鼠标输入接口不会进行按键或移动监听。序列号、设备路径不作为清单字段导出；厂商原始报文仍可能含设备标识。日志不自动上传。

日志包内含 `诊断摘要.txt`、`适配数据.json`、`run.json`、`inventory.jsonl`、逐接口 `.jsonl` 和子进程错误日志。日志包含所有阶段结果后才打包；遇到设备不响应也会保留已采集数据。

## 覆盖范围及限制

2026-10-26 首次采集增强（版本仍 v1.5.0，构建标识 20261026-comprehensive）：普通接口也导出值/按钮能力表和集合树；加入匿名物理设备分组和详细查询状态；复用监测程序已收录的专用电量协议。加入达摩鲨 M3 Pro 1915:0723 的接收器身份核对及电量查询，待实机验证。K03S 暂未确认专用电量命令。能力表是 Windows 解析结果，不冒充原始 USB 报告描述符字节。

v1.5 新增小米电竞鼠标 2 专用电量、DPI、回报率、档位指示色查询，严格限制为只读命令。旧版对该设备仅采集通用 Feature 快照；要核验新协议，需要采集一次新版日志。小米档位颜色不代表动态灯效。RK-G98 的共享 2.4G 接收器仍只采集基础资料，未套用有线协议。

2026-10-26 同版本更新：新增用户确认的 VGN V98（320F:5088、FF1C:0092）电量查询，尚待实机回复确认；修正 VXE R1 Pro Max 的型号、DPI 公式及指示灯解码。共用 USB ID 不作为所有同 ID 键盘的型号证据。JBL TOUR ONE M3 和小鸡 G7 Pro 仍采集基础资料，未确认其专用电量协议。主程序和诊断工具版本号均不递增。

v1.4.1 修正 VXE R1 NK 星闪接收器的 PAW3395SE DPI 解码、电量回复长度判断及身份数据长度标记。此前日志的原始数据仍然有效，无需仅为了这些解码修正重新采集。主程序版本从 v1.0.1 编号，与诊断工具独立。

这是一款统一的多品牌采集器，不需要每个品牌分别运行一个程序。能枚举设备并导出基础资料，不等于能读取该设备所有私有设置；当前没有依据声称“大部分品牌的全部型号都能完整读取”。

旧日志仍可用于后续分析。如果只是改电量程序界面，或者利用已有原始报文修正解码，不需要更新诊断器或重跑日志。只有新增必须发送的查询、修复采集缺陷等情况，才需要更新采集器；不应仅因为新增一个品牌名称就要求重新下载。v1.2 修正 ROG 灯区解析，v1.3 增加此前没有采集的怒喵回报率、鼠标与接收器灯光查询。

工具沿用项目内的 ASUS ROG、ATK/VXE/VGN CompX、Logitech HID++、Razer、MCHOSE 和部分 Lamzu/WLmouse 查询实现；怒喵采用项目中单独审查过的 AM 诊断模块，修正了旧版将 Pulsar 误作怒喵的路由。
这些是协议采集路径，不代表这些品牌的所有型号都已支持或经过硬件验证。共享接收器 VID/PID 不能确定实际品牌与型号，USB HID 也不能单独证明无线模式为 2.4G。未知键盘、未知固件和共享方案都可能只能采集原始资料。

每个功能记录 `read_status`、`candidate_value` 和 `write_status`。读取未确认不会伪装成 0% 电量或“不支持”；收到响应不代表支持写入。回报率字段是配置候选，不是实测输入频率。

本版没有 DPI 往返修改测试，不修改 DPI、回报率、灯光、配对或固件。采集包含发送已匹配协议的查询报文；“不修改设置”不等于 USB 总线上没有发送数据。

## 收到日志后的适配流程

先核对硬件、固件、报文结构和响应状态，再将已确认的电量读取接入设备电量程序。DPI、回报率和灯光调整还需核对设置命令、取值范围以及写后读取行为。日志不会自动解锁未知设备的调整功能。

如果一次采集不能确定协议，可能需要官方驱动资料，或“只改变一项设置”的 A/B 日志。对比方法：

```powershell
 .\多品牌外设诊断工具.exe --diff 快照A.zip 快照B.zip
```

字节差异是分析线索，不能单独证明写入指令。请同时说明两次采集之间修改了什么。

## 开发/排障参数

- `--output 路径`：指定日志保存目录。
- `--inventory-only`：只枚举硬件，不进行协议查询。
- `--pause`：结束后等待回车，便于查看输出。
- `--no-pause`：兼容旧版脚本；默认已经自动退出。
- `--all` / `--vid 0xXXXX`：扩大接口采集范围，不放开未知协议命令。

退出码 0 表示调度过程完成，2 表示至少一个工作进程失败、超时或未完成。即使退出码为 0，仍需检查具体查询是否响应。

源码：`tools/peripheral_diagnostic`。构建：使用带 PyInstaller 的 Python 运行 `build_diagnostic.py`。单元测试：`python -m unittest discover -s tools/peripheral_diagnostic -p test_diagnostic.py -v`。

## 系统电量诊断补充

本构建增加独立的 Windows 蓝牙与 XInput 系统采集，记录 `system_battery.jsonl`，并汇总到诊断 JSON 和摘要。蓝牙采集不再以 JBL 发射器出现为前提，系统未提供电量时明确记录缺失；系统采集失败不取消其他通道。当前版本不提供日志导入和本地协议绑定。
