## 修复与限制

- 主程序和诊断共用新增读取实现；记录发出的查询、收到的报告、校验结果、失败原因。雷柏为被动读取，不发送配置或唤醒命令。
- 梭鱼 X 返回电压而不是原生百分比。快照支持严格验证的电压标签，电压不会参与百分比低电量预警；退出临时通道失败时不会报告读取成功。
- 修复蓝牙诊断中“connected=false，但原因文字写设备已连接”的矛盾，保留真实断开/未知状态和缓存标记。
- 第三份日志还包含迈从 AX5 V2（5253:1020）。旧工具错误尝试了另一代的 Feature11/12，现停止该路径，保留描述符资料；未把AX5 V2算作适配完成。
- 本次不增加 DPI、回报率、灯效设置，不发送配对或固件命令。梭鱼 X 临时远端路由握手仅用于查询，退出也会写入日志。
- 没有把共用 USB ID 当成全部同品牌型号已支持。新增代码通过日志身份和合成电量回包测试，不等于这些用户设备已经完成实机电量验证。

## 使用

退出旧主程序，双击本目录里的 v1.0.2 程序。唤醒设备后刷新；雷柏首次启动可能要等待它的状态上报，后续监听保留最新有效结果。读不到时运行本构建诊断工具，再提交完整桌面 ZIP。无需导入日志。

## 协议依据

按接口与协议事实独立实现，未运行下载的项目或厂商程序。临时下载资料分析后删除，保留哈希清单。

- [HECATE G5 Max 实现和实测说明](https://github.com/SHISGAY114514/pulse-wireless-battery)：`edifier_proto.py`。
- [雷柏协议研究](https://github.com/pedro3z0/rapoo-software-linux)：官方型号清单确认VT3S V2 1464/4664、Nordic状态报文；与[BatteryHub](https://github.com/krisgfx9/Wireless-Device-Battery-Monitor)的 `rapoo_protocol.h` 交叉核对。状态枚举存在差异，故不推断充电。
- [SONiX读取实现](https://github.com/krisgfx9/Wireless-Device-Battery-Monitor/blob/main/src/drivers/sonix.cpp)：共用接收器的精确接口与读取命令，不构成青羽98 Pro本机实测。
- [梭鱼 X 专用协议研究](https://github.com/mehdibouchami/razer-barracuda-x-battery)：`Protocol.cs` 的 RACE/YS-Tech 帧结构、CRC和电压字段。本次不采用其电压百分比曲线与充电推测。
- [VGN读取实现](https://github.com/InkRain/2.4G-Battery-Check)和[实际硬件ID报告](https://github.com/ublue-os/bazzite/issues/5236)：结合用户日志的17字节 CompX 通道核对。两个来源对1A05连接方式表述不同，保留此限制。
- Hola87 Pro 的在线与型号回复来自用户日志；4A 读取沿用已核实的相同帧协议，未知签名、错误长度或校验失败不放行。

测试数量、EXE源码一致性、自检结果及SHA256见随包 `release-manifest-v1.0.2.json`。
