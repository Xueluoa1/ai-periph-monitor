# v31 DPI 扩展与验证边界

本次把已有118个USB控制标识中的117个鼠标标识加入DPI入口；另一个是充电底座，不适用DPI。另增加25个精确ROG型号/连接标识，以及Logitech HID++、VXE R1 Pro Max、LAMZU Atlantis协议系列、Scyrox V8、Pulsar指定report-8通道、MCHOSE A5第一代、WLmouse Beast X 4K、Endgame Gear、AJAZZ、RK M3、HECATE G3M Pro的独立通道。同一个型号可能包含多个连接标识，不能把数量当成鼠标款数或实测数量。

完整逐型号电量/DPI/回报率/灯光表见《v31-品牌型号功能支持清单.md》。本版没有宣称所有品牌所有鼠标都已适配，也没有给所有已识别电量设备强行加设置通道。

## 使用

1. 双击v31 EXE，在鼠标设置中扫描并选择设备。
2. 对原回报率/灯光目录中的设备，选择「读取 DPI 档位」；独立DPI设备直接读取。
3. 点击档位数值后的「修改」，输入数值并确认。程序保存后重新读取设备，确认实际结果。
4. 支持软件切换档位的通道提供「应用」。罗技、VAXEE、RK M3、Pulsar当前值通道和Endgame Gear不伪造完整可切换档位表。

RK、VAXEE、Pulsar只编辑当前档位。Endgame Gear能编辑已启用档位数值，但未读取到当前索引，因此不把第一个档位标成「当前」。罗技通过设备功能表读取允许的DPI值，接收器处于板载模式时不会自动切换模式。

## 读写约束

- 匹配VID/PID、HID用途页/用途和报告长度；共享接收器在可用协议内进一步核验配对/身份。仅凭品牌字符串不开放未知设备写入。
- 读取实际配置，不使用预设800/1600等值补齐失败回复，不把上次缓存当成设备当前值。
- 写入前重新读取，比较型号、配置层、档位、原始配置及相关控制字段；若已改变则要求重新读取。操作期间使用已有跨进程设备锁。
- 只修改目标DPI/档位字段，保持其他档位、颜色、保留位和配置项；完整读回与期望不一致即报错。写入超时不自动重试，提示可能部分生效。
- 分轴策略：新页面式、Incott、雷蛇等当前X/Y相等时同步修改；不等时保留Y。ROG/Atlantis/Scyrox未核实分轴写法，拒绝编辑不等的X/Y。旧ATK/怒喵同时修改X/Y，界面明确说明。
- Scyrox/Pulsar/G3M等需要临时配置会话；读配置使用协议的会话控制命令，退出时关闭会话。不是刷固件、清空配置或重新配对。读取页面不提交DPI设置。
- 新增功能不更换原有诊断器；稳定文件《多品牌外设诊断工具.exe》仍为v1.3。日志采集和主程序协议实现是两个发布对象。

## 未完成范围

Rapoo VT9 Pro缺少已核实DPI写入路径；Delux FA60共享接收器型号与Windows配置读回仍需确认；旧MCHOSE A7/M7和G7不能套用A7 V2/V3；旧怒喵接口/.100不能套用.97；其余VXE/VGN/Zaopin及共享3554型号仍需精确协议映射。旧ROG名称表中未核实PID也不因此获得DPI控制。上述条目保留原有条件电量支持，不标成完整适配。

## 验证

v31回归命令：在app目录使用.build-venv的Python运行unittest：verify_dpi_adapters、verify_dpi_more、verify_dpi_special、verify_dpi_ui、verify_mouse_features、verify_mouse_controls、verify_vendor_controls、verify_am_dpi、verify_am_battery、verify_am_controls、verify_atk_x1、verify_peripheral_protocols、verify_wireless_battery、verify_device_manager、verify_device_visibility、verify_tray_menu、verify_setting_fields。

共195项通过，包含40项新增DPI协议测试和3项DPI界面测试，其余为原功能回归。模拟测试覆盖报文、校验、身份变更、过期配置、非目标字段保留、禁止自动模式切换、写入后读回失败、会话关闭等。测试没有修改真实鼠标设置；不能替代所有新增型号实机验证。

打包后另检查新增模块与源文件一致、Tcl/Tk完整、EXE的只读设备自检退出码；实际结果与体积写入release-manifest-v31.json。
