## 已确认型号

用户确认日志 46d63078 的鼠标为 VXE 蜻蜓 R1 星闪版，键盘为 RK-G98。R1 的 CID/MID 2/67 与原 R1 NK 编码一致，沿用 v1.0.1 电量、DPI、回报率支持，修正显示名称。

RK-G98 仅确认用户所持设备对应 25A7:FA70、FF02:0002、Feature 8 的接收器。该 ID 不是独占型号 ID；此定制版本以“用户确认的共享接收器”显示，仍允许用户改名。不得将用户确认升级为适用于所有同 ID 设备的自动型号识别证据。

查阅 [Kludge Knight](https://github.com/vinc3m1/kludgeknight) 的 HIDDeviceManager.ts：其 RK 配置通道为 VID 258A、Usage 0001:0080、有线连接，和用户日志里的接口不同。此次未把有线配置命令发往 2.4G 接收器。电量与灯效仍待对应协议。

## 小米电竞鼠标 2

日志 382641e5 确认 VID:PID 2717:5111、FFEF:0000、Input/Output/Feature 均 64 字节，Report ID 5，描述符 `Mi Gaming Mouse 2 Receiver`。唯一 Feature 快照以 `05 51 2C 01` 开头，不是匹配的有效电量或 DPI 查询回复，不可据此声称 81% 或 44% 电量。

协议事实来自 [小米 G-HUB 网页驱动](https://d.mihub.fun)，跳转到 `https://web.mieco.net/yuemi--manual/mouse/h/p/index.html`，2026-10-24 分析 M002 实现。此次仅解析公开脚本，未执行下载代码或安装程序。实现独立编写，未复制网页驱动的代码。

- 脚本 `index-BbzxWOJP.js` SHA256：`a93a4b1af62c120faa9a64b1cd67bbae3b6d723b36d5acf830f5bc6e210473f6`。
- 页面还加载 `Performance-C4sfCAsZ.js`；实际 M002 设备性能逻辑在主脚本中。
- 精确接口支持 2717:5110（USB，目标 0）、2717:5111（接收器，目标 1），FFEF:0000；日志只验证了 5111 描述符。
- Windows Feature 报文共 64 字节，首字节 05；请求后依次为目标、命令、声明长度、数据。接收响应核对 Report ID、目标状态、命令和长度。
- 电量读取 16：3 字节负载依次为充电状态、电量、温度字段。状态 2 表示充电，0/1 表示非充电；拒绝未知状态。温度未对外解释。
- 当前配置层读取 80；本版仅接受层 1–5，不修改配置层。
- DPI 档位信息读 2B、写 2C，负载为配置层、启用档数、活动档（零基）；最多 5 档。
- DPI 档位读 2D，请求为配置层、档位；返回为配置层、档位、X 两字节小端、RGB 三字节、独立 Y 开关、Y 两字节小端。写 2E 沿用官方声明长度 7 及完整负载格式。范围 100–40000、整数步进。普通编辑同步 X/Y；独立 X/Y 开启时禁用数值修改，仍可切换档位和修改颜色。
- 回报率读 25、写 26，数据为配置层、07、回报率代码、00、00、性能模式、Motion Sync。代码 1/2/4/8/16/32/64 对应 125/250/500/1000/2000/4000/8000 Hz。保留当前性能模式及 Motion Sync；模式 2 最多 1000、模式 3 最多 4000、模式 4 最多 8000。程序不自动切换性能模式。
- 档位指示色可读写；未发现可接入的独立动态灯效/亮度控制，本版不虚构此功能。
- 每次写前获取新配置并比较，写后重新查询比较所有已读取档位、颜色、配置层、回报率附加字段。设置请求不自动重发，超时或不匹配明确报错。
- 诊断工具独立使用查询白名单，仅允许 16/80/2B/2D/25；不允许 2C/2E/26 或复位、宏、OTA 等命令。电量与配置查询分别保留结果，配置失败不丢弃电量。

## 已做与未做的验证

日志已验证设备身份和接口形状。专用电量、DPI、颜色、回报率尚无实机回复，协议实现经过模拟帧、异常状态、过期快照、读回失败、禁止重发和隐藏 Tk 界面测试。模拟电量 44% 等测试数值不代表用户鼠标的实际状态。

新版诊断工具需要额外发送此前未发送的专用读取命令，因此若要验证实机协议，需要用新版采集一次小米日志。此次旧日志仍保留且无需修改。临时下载的网页 HTML、JS 和 RK 源码 ZIP 分析后删除，只保留协议事实和哈希记录。
